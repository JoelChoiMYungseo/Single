# RULES.md — 불변 제약

> 이 파일에는 위반 시 시스템이 실제로 망가지는 규칙만 담는다.
> "코드가 지저분해진다"는 망가진 것이 아니다.
> "에디터가 3분 멈추거나, GUID 참조가 깨지거나, 빌드가 실패하거나, 
>  유저 저장본이 로드 불가능해지는 것"이 망가진 것이다.

---

### RULE-01 Domain Reload를 트리거하지 않는다

**위반 시:** 에디터가 3분 이상 멈추고 모든 static 상태가 초기화된다.

금지 행위:
- `[InitializeOnLoad]` 어트리뷰트 신규 추가
- `.asmdef` 파일의 `autoReferenced` 값을 `true`로 변경
- `.asmdef` 파일 구조 임의 변경 (의존성 순환 유발)

위반 여부 확인:

```bash
grep -rE '\[InitializeOnLoad\]' Assets/ --include="*.cs"
grep -r  '"autoReferenced": true' Assets/
```

### RULE-02 ~~Unity 자산 파일을 직접 편집하거나 생성하지 않는다~~ — 2026-08-24 아키텍트 해제

> **해제됨.** 프로토타입을 씬에 직접 조립하는 속도가 우선이라는 아키텍트 판단으로,
> `.prefab`/`.unity`/`.asset`/`.mat` 등을 Claude가 텍스트로 직접 편집·생성하는 것을 허용한다.
> 아래는 해제 전 근거였던 위험 — 알고 진행한다:
>
> **위험:** 이 파일들은 GUID 기반 참조로 얽혀 있다. 텍스트 편집 중 GUID가 어긋나면
> "Missing script"·참조 끊김이 발생하고, Unity가 그 사이 파일을 다시 저장하면
> git revert로 되돌릴 수 없는 상태가 될 수 있다. 문제가 생기면 Unity Editor에서
> 수동 재작업이 필요할 수 있다.
>
> **완화책:** 씬/프리팹을 편집하기 전 `git status`로 미저장 변경이 없는지 확인하고,
> 편집 후에는 Unity Editor를 열어 콘솔에 에러(특히 GUID/참조 관련)가 없는지
> 사용자가 확인하는 것을 권장한다.
>
> `.meta`는 여전히 Unity가 자동 관리하는 GUID 저장소이므로, 기존 `.meta`의
> GUID 값 자체를 손으로 바꾸는 것은 계속 피한다 (새 `.meta` 생성은 무방).

### RULE-03 물리 연산은 FixedUpdate에서만 수행한다

**위반 시:** 프레임 레이트에 따라 물리 시뮬레이션이 불안정해진다.
         VR 90Hz 환경에서 점프/이동이 기기마다 달라진다.

- `Rigidbody.AddForce`, `MovePosition`, `velocity` 직접 조작은 
  `FixedUpdate()`에서만 호출한다.
- `Update()`에서 물리 API를 호출하지 않는다.

### RULE-04 ~~ProjectSettings는 Claude가 직접 수정하지 않는다~~ — 2026-08-24 아키텍트 해제

> **해제됨.** `ProjectSettings/` 하위 파일(레이어, XR, 물리 등)을 Claude가 직접
> 수정하는 것을 허용한다.
>
> **위험:** 이 폴더의 파일 다수는 텍스트지만 일부(`GlobalGameManagers` 등)는
> 바이너리라 병합이 불가능하다. 잘못된 값 하나가 프로젝트 전체 설정을 꼬이게 할 수 있다.
>
> **완화책:** 변경 전 현재 값을 확인해 두고, 변경 폭이 큰 경우(레이어 추가처럼
> 되돌리기 번거로운 것) 무엇을 바꾸는지 간단히 알린 뒤 진행한다.
